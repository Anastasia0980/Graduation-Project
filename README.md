# 强化学习课程智能体测评平台

本项目是一个强化学习智能体测评平台，采用 `Vue 3 + Spring Boot + Python` 的分层架构，覆盖任务发布、模型提交、自动评测、多人对战、排行榜展示与成绩导出等完整流程。

平台既支持单智能体任务的自动评分，也支持对战型任务的胜率评估，适合作为强化学习课程平台、实验评测平台或二次开发基础工程。

## 项目简介

在强化学习实验教学或智能体评测场景中，通常会遇到以下问题：

- 学生实验结果提交格式不统一，教师难以批量评阅。
- 不同算法、不同环境的评测标准不一致，结果横向对比困难。
- 训练过程、评测结果和排名信息分散，缺乏统一平台管理。
- 对抗类任务依赖人工组织与本地运行，不利于课程规模化实施。

本项目将前端交互、后端任务管理与 Python 评测脚本整合到统一系统中，使使用者能够在线发布任务、提交模型、自动完成评测、记录结果并生成排行榜，从而形成完整的评测闭环。

从仓库结构和实现逻辑来看，本项目并不是单一的“强化学习训练脚本集合”，而是一个完整的平台型系统，强调自动化测评、结果管理和多角色协同能力。

## 项目亮点

- 多角色平台：支持学生、教师、管理员三类用户。
- 自动化评测：后端调度 Python 脚本，对提交的模型进行统一评测。
- 对战模式：支持多人博弈环境下的模型对抗与结果统计。
- 基线对照：可将学生模型与 baseline 模型进行对比评估。
- 可视化结果：支持排行榜、历史记录、详细评测结果与视频产出。
- 教学闭环：覆盖任务发布、提交、评测、成绩管理与资源下载。

## 业务流程

平台的典型工作流程可以概括为：

1. 教师创建实验任务，设置评测环境、算法类型、阶段配置或基线模型。
2. 学生进入任务页面，查看要求并上传自己的模型文件和配置文件。
3. 后端接收提交，创建评测记录，并调用对应的 Python 评测脚本。
4. Python 脚本运行模型，输出分数、统计信息和可选视频文件。
5. 后端解析结果并写入数据库。
6. 前端展示历史记录、排行榜、详细成绩和挑战结果。

## 用户角色

### 学生端

学生是平台的主要使用者之一，典型操作包括：

- 注册与登录平台
- 加入班级
- 查看教师发布的实验任务
- 下载模板或资源文件
- 上传训练后的模型和配置
- 查看评测结果、历史记录和排行榜
- 在对战类任务中选择主模型并发起挑战

### 教师端

教师负责教学组织与测评规则配置，典型操作包括：

- 创建和发布实验任务
- 配置任务环境、算法要求和评测模式
- 查看学生提交记录与完成情况
- 维护班级信息与学生列表
- 查看统计结果与导出成绩
- 管理对战环境与平台资源

### 管理员端

管理员主要面向平台运行维护，负责系统级内容或后台信息管理。虽然当前 README 不展开管理员业务细节，但从整体结构可以看出系统预留了后台管理能力。

## 核心能力

### 1. 单智能体课程评测

教师可发布实验任务，学生提交模型文件和配置后，后端会自动调用 Python 评测脚本执行测试，并保存：

- 评测分数
- 过程结果
- 排行榜信息
- 可选视频输出

在该模式下，平台通常会围绕单个环境或阶段任务进行评分。学生上传自己的训练结果后，后端将评测参数传递给 Python 脚本，由脚本统一执行测试并输出标准化结果，保证不同学生提交在同一套规则下比较。

同时，平台以提供基线模型和闯关式关卡作为亮点，允许自定义关卡环境参数、调整选取不同算法下的各基线模型最终奖励表现以控制关卡难度，促进学生自主探索、勇于闯关的积极性与主动性。

### 2. 多人对战评测

平台支持对战型环境中的模型对抗，可用于双人博弈类强化学习任务。

- 学生可上传候选模型
- 可设置主模型参与挑战
- 系统自动统计胜负结果
- 支持保存历史对战记录

与单智能体任务不同，对战模式更强调策略之间的相互博弈。平台通过候选模型、主模型和挑战流程组织学生之间的对抗，可用于：

- 博弈类课程实验
- 课堂竞赛与排名
- 不同算法策略的对比分析
- 模型鲁棒性观察

### 3. 教学管理能力

- 班级管理
- 任务发布与管理
- 学生提交记录查看
- 成绩导出
- 排行榜展示
- 资源下载

## 提交方式

建议学生提交内容尽量保持结构清晰。例如：

```text
student_submission/
├─ config.json
├─ model.pt
└─ train.py
```

其中：

- `config.json`：保存算法类型、环境参数或模型配置
- `model.pt`：保存训练完成后的权重文件
- `train.py`：训练脚本或与模型配套的实现代码

具体字段要求仍应以教师发布任务时给出的模板与说明为准。

## 快速开始

> 注意：该项目包含若干需要手动配置的运行参数。首次运行前，请先检查后端配置文件中的 Python 解释器、Conda 环境、工作目录、数据库和 Redis 等配置项。README 中不展示任何真实机器路径，建议你根据自己的本地环境自行填写。

### 1. 环境要求

- Node.js `18.20.8`
- Java `17`
- Python `3.9`
- MySQL
- Redis
- Conda

### 2. 前端启动

进入 `frontend` 目录后执行：

```bash
npm install
npm run serve
```

默认开发地址：

- 前端：`http://localhost:8081`

### 3. 后端启动

进入 `RL-platform-setup-framework` 目录后执行：

```bash
mvnw.cmd spring-boot:run
```

如果本机已安装 Maven，也可使用：

```bash
mvn spring-boot:run
```

默认开发地址：

- 后端：`http://localhost:8080`

### 4. Python 依赖安装

根目录依赖：

```bash
pip install -r requirements.txt
```

如果以平台评测脚本为主，建议同时安装：

```bash
pip install -r RL-platform-setup-framework/scripts/requirements.txt
```

### 5. 数据库与缓存准备

启动后端前，建议先准备以下基础服务：

- MySQL
- Redis

后端启动时会依赖数据库连接和缓存连接。如果这些服务未正确启动或配置不一致，平台的登录、任务管理和评测记录功能可能无法正常使用。

### 6. 最小启动顺序

建议按以下顺序启动：

1. 启动 MySQL
2. 启动 Redis
3. 配置后端 `application-dev.yml`
4. 启动后端服务
5. 启动前端服务
6. 通过浏览器访问前端页面进行验证
